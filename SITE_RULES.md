# Правила Public Website «Ваш Финдир» — дизайн-система v2

## Статус и граница

Этот документ — Source of Truth для визуальной системы публичного Symfony/Twig-сайта. Дизайн-пакет `design-system-inbox/handoff` — референс для переноса, не runtime-зависимость. `Design System.dc.html` — визуальный эталон. Административный интерфейс и React-пакет из handoff не входят в Public Website. Опубликованные тексты, факты, URL, SEO и форма заявки сохраняют свои контракты.

Новые и изменяемые страницы собираются из `site/templates/website/pages/`, секций `sections/` и повторно используемых `components/`. Страница задаёт состав секций и контент; секция задаёт layout; компонент отвечает за одно поле или UI-паттерн. Twig не делает запросов и не содержит бизнес-правил.

## Сборка и источник токенов

Tailwind CSS `4.3.3` работает только при сборке. Единственный исходный stylesheet — `site/assets/styles/website/app.css`; единственный compiled stylesheet — `site/public/assets/website/app.css`. `make assets`, `make asset-version`, `make assets-check`, `make ci` — проектные команды. Node, Style Dictionary, CSS Modules, React runtime и CSS/JS из handoff не подключаются к сайту. CSS и JavaScript inline в Twig запрещены, за исключением существующего JSON-LD script с сериализованными данными. Bootstrap запрещён.

Канонические значения v2 находятся в token/theme blocks `app.css`. `@theme inline` связывает Tailwind utilities с **семантическими** `--vf-color-*`; в Twig не используют примитивы `--vf-ink-*` и `--vf-crimson-*`. Палитра Tailwind по умолчанию отключена. Новое значение добавляют в token block только с ролью, проверенным контрастом и отражением в `/ui-kit`. Произвольные значения Tailwind (`[#…]`, `[13px]`), page-specific HEX, второй stylesheet и старые aliases v1 запрещены.

Сверка пакета: `tokens.css` содержит тёмную тему `[data-theme="dark"]`, цвета overlay, `--vf-font-mono`, `--vf-t8`, компонентные токены `--vf-button-*`, `--vf-input-*`, `--vf-card-*`, `--vf-logo-*`, которых нет или недостаточно в `tokens.json`. Они перенесены в `app.css` как канонический набор. Chart tokens из CSS сохранены как примитивы пакета, но публичные страницы не используют их без графика. Не создавать второй источник значений в Twig или отдельном CSS.

Не заменять это ручными `text-white` или цветами примитивов. Тёмный Footer и демонстрация в UI-kit используют этот контракт. Главный Hero — светлый, текстовый, без изображения.

Статусы: `success`, `warning`, `error`, `info` имеют отдельные `fg`, `bg`, `border` tokens (`--vf-color-<status>`, `--vf-color-<status>-bg`, `--vf-color-<status>-border`). Статус всегда сопровождается текстом. Цвета статусов не используются для украшения секций. Состояния кнопки: default, hover, active, focus-visible, disabled; у формы дополнительно error и success. Focus видим через `--vf-shadow-focus`, в том числе в тёмном контексте. Проверять normal text ≥ 4.5:1, крупный текст и границы UI ≥ 3:1; не использовать слабоконтрастный foreground для важной информации. `border-strong` в обеих темах и `accent-active` в тёмной теме отклоняются от handoff ради контраста control и текста кнопки.

## Типографика и геометрия

Inter — основной текст, Manrope — заголовки и display. Оба шрифта размещены локально с лицензиями OFL и `font-display: swap`; внешние font CDN запрещены. Шкала пакета: T1 36/44 mobile, 48/56 desktop, 800; T2 30/38 mobile, 36/44 desktop, 800; T3 20/28, 700; T4 18/28, 400; T5 16/26, 400; T6 14/22, 500; T7 12/18, 500; T8 30/38, 800 для чисел. В Tailwind используют `text-t1`…`text-t8`; заголовки также получают семантическую HTML-разметку. Один H1 на страницу. Длинный текст ограничен `--vf-measure: 720px`. Не вводить page-specific размеры и принудительные `<br>` для переноса заголовков.

Spacing v2: 0, 2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 96 px (`--vf-space-*`). Container max 1200px; внутренний отступ 16px mobile, 32px tablet через `.vf-container`; gutter 16/24/32. Breakpoints: md 768px, lg 1024px, xl 1440px. Control height 48/40/32px, touch target минимум 44px, input text 16px; radii 0/4/8/12/16/24/full; shadows none/sm/md/lg. Соседние блоки разделяются `gap` по шкале. Section vertical padding 48/64/80px. Горизонтального скролла на 320px не должно быть; длинные таблицы прокручиваются внутри доступной region.

## Компоненты и секции

Production components: Button (`primary`, `secondary`, `ghost`), Input, Select, Textarea, Checkbox, Card, Alert, Badge, Breadcrumbs, Accordion, Pagination, Navbar, Footer, Cookie notice. Badge поддерживает `default`, `accent`, `accent-solid` для залитой метки на технической шапке и статусные tones; `accent` используется в техническом каталоге на тёмной вводной области. Классы состояний Button — полные статические Tailwind strings. Не создавать page-specific копию markup. Form labels связаны с control; ошибки показываются текстом и `aria-invalid`, не одним цветом. Согласие не отмечено заранее. Доступное мобильное меню использует native dialog и сохраняет `data-vf-menu-*` hooks.

Production sections: Hero, Content, Text list, Grid, Steps, Paths, Split, Quote, Comparison, FAQ, Case preview, Lead form, CTA, Article. `/ui-kit` и `/ui-kit/sections` рендерят эти же partials и production states, а не параллельную библиотеку; маршруты noindex. Демонстрационная форма не имеет submit action. Новые секции появляются при подтверждённой потребности в другом layout, а не ради другого цвета фона. Примеры цен, возможностей кабинета и неподтверждённое фото из дизайн-макета не публикуются.

HTML статьи из Markdown оформляется только через `.vf-article-body` в `app.css` с семантическими токенами. Таблицы имеют прокрутку внутри контейнера. Ссылки и keyboard focus видимы; `prefers-reduced-motion` выключает переходы. На малых экранах CTA, навигация и формы сохраняют touch targets и читаемость.

## Контракты поведения и SEO

Форма заявки отправляет `POST /lead` с CSRF, полями и `data-vf-*` hooks текущего контракта. Публичный GET не открывает session без необходимости. Cookies notice сохраняет выбор и доступен с клавиатуры. Старые публичные URL нельзя менять без redirect. Layout централизованно выводит title, description, robots, canonical, Open Graph, Twitter и JSON-LD. Метаданные страниц и published/draft visibility не зависят от оформления. OG image для v2 использует новый URL из-за immutable cache. Website assets имеют release query — первые 12 знаков SHA-256 конкатенации `app.css`, `analytics.js`, `navigation.js`, `metrika.js`, `ui-kit-logo.js`, `ui-kit-navigation.js`; после `make assets` перенести `make asset-version` в layout.

## Приёмка изменения

Перед выпуском проверить исходники, `make assets-check`, `make ci`, основные публичные маршруты, блог, пагинацию, форму с ошибкой и успехом, JSON-LD, cookie, UI-kit и страницы ошибок. Браузером проверить 320, 375, 768, 1024, 1440px, menu → form → result, отсутствие горизонтального скролла, клавиатурный focus и reduced motion. Self-review полного diff и независимое ревью через Claude Code обязательны по `AGENTS.md`. Админ, Traefik и `conwix/` в эту задачу не входят.

## Архитектура секций и выбор паттерна

Page хранит порядок секций и данные. Section принимает явные параметры: `id`, `title`, `text`, `eyebrow`, действия и структурированные элементы. Section не запрашивает данные, не вычисляет бизнес-состояние и не хранит копию общего компонента. Общий `_base.html.twig` задаёт `<section>`, заголовочную связь, вертикальные отступы и `.vf-container`. На технической странице `/ui-kit` параметр `catalog_embed` выводит содержимое существующей секции без второго контейнера и вертикальных отступов внутри нумерованного блока; на production-страницах он не используется. Section может задать `data-theme="dark"` только для реального тёмного контекста. Соседние секции не чередуют фон декоративно.

Для короткого тезиса выбрать Text list; для равноправных карточек — Grid; для последовательности — Steps; для развилки вариантов — Paths; для доказательства — Case preview или Quote с подтверждённым источником; для данных — Comparison с заголовками таблицы и горизонтальной прокруткой внутри региона; для раскрываемых ответов — FAQ/Accordion; для действия — CTA или Lead form. Split нужен только при осмысленном разделении текста и media. Не создавать вторую секцию с тем же смыслом ради отличающегося фона или ради одной страницы.

Реальные изображения доступны только если права и происхождение подтверждены. Демо-media остаётся в техническом каталоге с `aria-hidden`; оно не становится опубликованным фактом. Цены, метрики, отзывы, имена клиентов и возможности продукта не выводятся без источника. Главная использует светлый Hero без иллюстрации. UI-kit — технический каталог с `noindex`, не коммерческая страница.

## Accessibility baseline

- Структура заголовков соответствует смыслу; один H1 на странице, секции связаны с заголовком через `aria-labelledby`.
- Интерактивный control доступен с клавиатуры; минимальная цель 44×44px там, где элемент предназначен для касания. Focus visible не скрывается. Для CTA на акцентной поверхности применяется белый внешний outline.
- Поле имеет видимый label; required, disabled и error передаются нативными атрибутами и `aria-invalid`/`aria-describedby`. Текст ошибки или статуса виден без распознавания цвета. Согласие на обработку данных никогда не отмечено заранее.
- Навигация помечена `nav` и именем области. Мобильное меню — native dialog с возвратом фокуса, Escape и корректным `aria-expanded`. Cookie notice доступен с клавиатуры и не крадёт фокус.
- Breadcrumbs — `nav` + `ol`, последний пункт имеет `aria-current="page"`. У production partial разделитель по умолчанию `/`; технический образец раздела 16 задаёт `›` через явный параметр `separator`, сохраняя декоративный разделитель `aria-hidden`. Accordion использует `details`/`summary` и настоящий heading. Таблицы содержат заголовки строк и столбцов, прокрутка ограничена регионом с клавиатурным доступом.
- Нормальный текст имеет контраст не ниже 4.5:1, крупный текст и граница control не ниже 3:1 в светлой и тёмной теме. Ошибка не определяется одним цветом; focus показывается кольцом, ошибка — рамкой и сообщением.
- `prefers-reduced-motion: reduce` выключает переходы. Не добавлять анимацию ради украшения. Документ использует нативную полосу прокрутки браузера; не создавать собственный scrollbar, принудительную ширину или ложный gutter.
- На 320, 375, 768, 1024 и 1440px нет горизонтальной прокрутки документа. Заголовки и длинные слова переносятся без обрезания; формы и меню остаются пригодными к работе.

## CSS и JavaScript

CSS содержит canonical tokens, Tailwind theme mapping, базовую типографику, Markdown article styling, локальные стили технической витрины `/ui-kit` и только те custom utilities, которые выражают общий контракт (`vf-container`, `grid-auto-fit`, `navigation-drawer-width`). Технический `/ui-kit` использует `data-vf-swatch` для показа примитивных шкал; селекторы свотчей в том же `app.css` ссылаются только на canonical `--vf-ink-*`, `--vf-crimson-*` и `--vf-chart-*`. Компоненты используют статические Tailwind classes и семантические tokens; классы не конструируются из динамического имени цвета. Hex/rgb как CSS-значения допустимы только внутри canonical token block и в графическом asset. Точные геометрические размеры эталона и образцы примитивов допускаются лишь в локальных стилях технического `/ui-kit`; production-страницы используют шкалу и семантические роли. Технический `/ui-kit` печатает HEX, rgb и коэффициенты контраста как справочные текстовые метки, а заливку образцов берёт из CSS-токенов; inline-стили в Twig запрещены. Browser не загружает Tailwind runtime или второй stylesheet.

Разделы 06–10 `/ui-kit` — статические технические образцы шкал и состояний из эталона, без выполнения операций. Двенадцать иконок Lucide v0.460.0 хранятся локально в `site/public/assets/ui-kit/lucide/` вместе с лицензией; внешний icon CDN не используется. Знаки Telegram и VK из Simple Icons v13.0.0, знак MAX из Arcticons хранятся локально в `site/public/assets/ui-kit/social/`. Атрибуция MAX указана в `ATTRIBUTION.md` и рядом с образцом; образцы не означают действующих каналов компании. Широкие сетки и матрица состояний прокручиваются только внутри подписанных областей, без горизонтальной прокрутки документа. Каталог `/ui-kit/sections` сохраняет образцы действующих production-компонентов.

JavaScript остаётся в `site/assets/scripts/website/` и обслуживает навигацию, cookie, аналитику, формы и технические образцы `/ui-kit`. Генератор логотипа загружается только в каталоге, применяет формулы эталона к десяти сочетаниям размера и темы, показывает выбранное состояние через `aria-pressed`. Техническое меню раздела 16 также загружается только на `/ui-kit`: его локальные панели, поиск по статическому демо-списку и сокращённые крошки не изменяют production Navbar и не создают функции кабинета. Кнопки раскрытия используют `aria-controls`, `aria-expanded`, `hidden`; независимые образцы могут быть открыты одновременно. Не вводить JS ради стилизации. Сохранять `data-vf-*` hooks и CSRF при работе с формой. Новые JS состояния должны получать v2-классы, присутствующие в Tailwind source scan. Проверка v1 aliases охватывает CSS, Twig и website JS.

## Антипаттерны и расширение системы

Не добавлять декоративные gradient, случайные тени, произвольные оттенки Crimson/Navy, несимметричные случайные отступы, большие наборы цветных карточек, layout «три карточки на каждую тему», лишние иконки, псевдографики и анимацию ради эффекта. Не публиковать макетный контент как факт. Не исправлять плохой перенос заголовка `<br>` или размером только одной страницы. Не копировать Twig markup компонентов между страницами.

Если нужного решения нет:

1. Описать пользовательскую задачу и существующий компонент или секцию, которая почти подходит.
2. Проверить, можно ли выразить вариант существующими параметрами и семантическими токенами без нового CSS.
3. Если нет, определить роль нового token или границу нового component/section, состояния, светлую и тёмную темы, адаптивность и доступность.
4. Обновить `SITE_RULES.md`, production partial, `/ui-kit`, исходный guard и нужный функциональный тест одновременно.
5. Пересобрать assets, обновить release hash и выполнить `make ci` и браузерный просмотр.

Запреты и исключения меняются документированным решением по подтверждённой задаче; `stylelint-disable` или локальный inline style не считаются решением. План этапа фиксирует отклонение от handoff и причину, как в случае границы control.
