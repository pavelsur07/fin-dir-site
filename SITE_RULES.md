# Правила Public Website «Ваш Финдир»

## Граница

Публичные страницы рендерятся Symfony/Twig. Страница задаёт состав секций и контент, секция задаёт структуру, компонент отвечает за повторяемый элемент. Twig не делает запросов к базе и не содержит бизнес-правил. Опубликованные тексты, URL, SEO и форма заявки сохраняют свои контракты.

Шаблоны страниц в `site/templates/website/pages/` сгруппированы по назначению: `marketing/` — главная и страницы о компании, услугах, кейсах и партнёрах; `publication/` — список и статья «Газеты»; `legal/` — юридические документы; `lead/` — результат заявки; `errors/` — страницы ошибок. Страница собирает контент, секция представляет крупный повторяемый блок, компонент — небольшой повторяемый элемент. Включаемым фрагментам передавать явные аргументы через `with … only`. Для существующих фрагментов достаточно Twig partials.

## Tailwind

Tailwind CSS 4.3.3 собирается командой `make assets` и не загружается в браузере как runtime. Единственный исходный файл — `site/assets/styles/website/app.css`; в нём допускаются импорт Tailwind, импорты `vf-fonts.css` и `vf-theme.css`, согласованный блок `@theme` с токенами navy/red/paper, правило `.dark` для success/warning и директивы `@source` для Twig, JavaScript и Markdown рендерера. Результат сборки — `site/public/assets/website/app.css`. Административные Twig шаблоны до появления React Admin используют эту же сборку.

Для оформления использовать классы темы из `design-system-inbox/` и согласованного блока `@theme` в `app.css`, а не прочие классы стандартной темы Tailwind. Источник прежней темы и правил миграции — `design-system-inbox/README.md`; `vf-theme.css` вручную не редактировать. Одноимённые токены из `app.css` переопределяют прежние значения, остальные токены сохраняются. В `.dark` success/warning возвращаются к семантическим тёмным значениям через правило `@layer base` в `app.css`, чтобы сохранить контраст. Новые кнопки используют red-600/700 только для главного действия, остальные — secondary с navy-900. В шаблонах не использовать inline оформление и произвольные значения в квадратных скобках. Не добавлять JavaScript, который задаёт CSS свойства. Классы, меняющиеся из JavaScript, должны присутствовать в исходниках, которые сканирует Tailwind.

Страницы наследуют `website/layouts/page.html.twig`; до миграции по `design-system-inbox/MIGRATION.md` они сохраняют минимальную разметку без оформления, иконки — Lucide через `components/_icon.html.twig`, inline SVG, без JS и без CDN, соцсети в футере — текстовые ссылки. Компоненты и секции в `site/templates/website/` переиспользуют существующие Twig partials. Не копировать их разметку между страницами. Состояния форм и кнопок выражать полными строками классов темы; не конструировать имя класса из переменной цвета. Для тёмной области явно указывать её классы в Twig.

## Поведение и доступность

Форма заявки отправляет `POST /lead` с CSRF и сохраняет существующие поля и `data-vf-*` hooks. Анонимный GET не начинает session без необходимости. Уведомление о cookie сохраняет выбор; мобильное меню доступно с клавиатуры. Не менять публичные URL без redirect. На странице один H1, форма имеет видимые labels и текст ошибок, интерактивные элементы имеют видимый focus. Уважать `prefers-reduced-motion`. Проверять отсутствие горизонтальной прокрутки на ширинах 320, 375, 768, 1024 и 1440px.

Layout централизованно выводит title, description, robots, canonical, Open Graph, Twitter и JSON-LD.

## Проверка

После изменения Twig, JavaScript или Tailwind entrypoint выполнить `make assets`, перенести значение `make asset-version` в оба layout и запустить `make assets-check` и `make ci`. Проверить основные публичные страницы, блог, форму заявки, cookie, мобильное меню, страницы ошибок и временный Twig Admin в браузере.
