# Уведомления о заявках в Telegram — настройка

**Статус на 2026-09-23:** код задеплоен, бот ещё не создан. Заявки с сайта уже
сохраняются и видны в админке `/admin/leads`, но уведомления в Telegram не уходят.
В карточке заявки написано «уведомления выключены (нет настроек Telegram)».

## Какие данные нужно внести в GitHub secrets

| Secret | Что это | Пример формата |
|---|---|---|
| `VF_TELEGRAM_BOT_TOKEN` | токен бота от @BotFather | `7412345678:AAH4x...` (цифры, двоеточие, ~35 символов) |
| `VF_TELEGRAM_LEAD_CHAT_ID` | id чата, куда бот пишет заявки | группа: `-1001234567890`, личный чат: `123456789` |

Где их заводить: GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
Имена — ровно такие, как в таблице.

Оба секрета нужны вместе: если задан только один, уведомления остаются выключенными.

## Шаг 1. Создать бота

1. В Telegram открыть **@BotFather** и отправить `/newbot`.
2. Указать имя, например «Ваш Финдир — заявки», и username, который оканчивается на `bot`, например `vashfindir_leads_bot`.
3. BotFather пришлёт **токен**. Это значение для `VF_TELEGRAM_BOT_TOKEN`.
4. Токен даёт полный доступ к боту: никому не пересылать, не коммитить и не вставлять в задачи и чаты.

## Шаг 2. Выбрать чат для заявок

**Вариант А — группа (рекомендуется).** Заявки видят все, кто в группе, и можно добавить второго менеджера.

1. Создать группу, например «Заявки с сайта», и добавить в неё бота.
2. Написать в группе любое сообщение, например `/start`.
3. Открыть в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, подставив токен из шага 1.
4. В ответе найти `"chat":{"id":-100...` — это значение для `VF_TELEGRAM_LEAD_CHAT_ID` (со знаком минус).
5. Если `result` пустой, отправить в группу ещё одно сообщение и обновить страницу.

**Вариант Б — личный чат с ботом.**

1. Найти бота по username и нажать **Start**.
2. Открыть ту же ссылку `getUpdates` и взять `"chat":{"id":123456789` — положительное число.

Ссылку `getUpdates` с токеном после этого закрыть и не сохранять в истории и закладках.

## Шаг 3. Внести секреты и перевыкатить

1. Завести оба секрета в GitHub (таблица выше).
2. Секреты подставляются в контейнеры при деплое, поэтому нужен новый деплой:
   - GitHub → **Actions → Deploy vashfindir to production → Run workflow** (ветка `master`). Это основной способ, коммит не нужен;
   - или **Re-run all jobs** у последнего успешного запуска: при перезапуске секреты берутся текущие.

   Обычный push в `master` запускает деплой, **только если** изменены `site/**`,
   `docker-compose.prod.yml` или сам workflow. Push одной документации деплой не запускает.

## Шаг 4. Проверить

1. Открыть `https://vashfindir.ru/` и отправить заявку с главной. Имя — например «Тест», контакт — свой.
2. В чат должно прийти сообщение «Новое обращение №…» со ссылкой «Открыть в админке». Больше в сообщении ничего нет, все подробности — в карточке по ссылке.
3. В админке в карточке заявки должно быть «Уведомление: отправлено …».
4. Удалить тестовую заявку: карточка → «Удалить обращение».

## Если сообщение не пришло

- В карточке заявки видна причина:
  - `Telegram API responded 401` — неверный токен;
  - `Telegram API responded 400` или `403` — неверный `chat_id`, либо бота нет в группе или его удалили оттуда;
  - `Telegram request failed` — сервер не достучался до Telegram (сеть или блокировка).
- После исправления секретов и нового деплоя дослать пропущенное:
  - кнопка **«Отправить повторно»** в карточке — основной способ;
  - или на сервере, из каталога деплоя: `docker compose -p vashfindir -f docker-compose.prod.yml run --rm site-php-cli php bin/console app:lead:notify-pending`. Команда досылает заявки, кроме спама, за последние 7 дней. Перед запуском в shell нужно экспортировать те же `VF_*` переменные, что и при деплое (`VF_SITE_APP_SECRET`, `VF_SITE_DB_PASSWORD`, `VF_ADMIN_PASSWORD_HASH`, `VF_TELEGRAM_*`): без них compose остановится на проверке `:?`.

## Что уходит в Telegram (152-ФЗ)

Только номер заявки и ссылка на её карточку в админке. **Ни данные формы, ни название формы, ни страница, ни ответы на вопросы, ни UTM-метки в Telegram не отправляются**, их видно только в админке. Поэтому трансграничной передачи персональных данных нет, и это совпадает с согласием на обработку данных (`/consent`, пункт 4): данные третьим лицам не передаются.

До 24.09.2026 в сообщении были ещё название формы, страница, ответы на вопросы квалификации и UTM (решение Stage 7). Их убрали, чтобы уведомление не противоречило согласию.

## Если токен утёк

1. @BotFather → `/mybots` → бот → **API Token → Revoke current token**.
2. Внести новый токен в `VF_TELEGRAM_BOT_TOKEN` и перевыкатить (шаг 3).

## Где это в коде

- отправка: `site/src/Lead/Adapter/TelegramLeadNotifier.php` (таймаут 3 секунды), текст сообщения: `LeadNotification.php`;
- переменные окружения: `docker-compose.prod.yml` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_LEAD_CHAT_ID`), `.github/workflows/deploy-vashfindir.yml` (export из secrets);
- по умолчанию значения пустые (`site/config/services.yaml`), поэтому без секретов сайт работает и заявки сохраняются.
