# `/ui-kit`: раздел 16 «Навигация» — план реализации

> **Для исполнителя:** выполнять задачи последовательно в отдельной рабочей ветке. Использовать `superpowers:executing-plans` и отмечать выполненные пункты. Основание: `docs/plan/UI_Kit_Reference_Audit_00_05.md` и визуальный эталон `design-system-inbox/Design System.dc.html`, раздел 16, строки 940–1225.

**Цель:** заменить текущие три ссылки в разделе 16 технической демонстрацией всех четырёх уровней навигации эталона, сохранив работу публичного сайта.

**Подход:** образцы сайта и кабинета остаются только внутри `/ui-kit`, без изменения production Navbar, маршрутов, авторизации и данных. Twig задаёт семантическую разметку и демонстрационные данные; локальный скрипт управляет раскрытием и выбором состояний; стили находятся в единственном `site/assets/styles/website/app.css`. Для существующих элементов сайта используются production компоненты там, где они передают тот же смысл. У образцов кабинета нет настоящих действий, аккаунтов или переходов.

**Стек:** Symfony/Twig, Tailwind build time, обычный JavaScript, PHPUnit/WebTestCase, Playwright для браузерной приёмки. Новых зависимостей нет.

**Основание и ограничения:** `docs/architecture/PATTERNS.md`, `SITE_RULES.md`, `AGENTS.md`, `docs/plan/UI_Kit_Reference_Audit_00_05.md`. Макет `Design System.dc.html` — источник состава и геометрии. Неподтверждённые тарифы, число операций, компании, имена, адреса и функции кабинета заменить явно демонстрационными нейтральными данными близкой длины. URL `/ui-kit`, `noindex`, один H1 и уже восстановленные разделы 00–05 сохранить. Работу других публичных страниц не менять.

## Граница этапа

- Входит весь раздел 16: 16.1 основное меню сайта с двумя раскрывающимися панелями и мобильным образцом; 16.2 меню компании и пользователя; 16.3 каркас кабинета с боковым меню, вкладками, пагинацией и нижней мобильной панелью; 16.4 хлебные крошки с вариантами, правилами и примером JSON-LD.
- Входит работающее раскрытие тех образцов, которые в эталоне интерактивны: «Возможности», «Для кого», мобильные группы, компания, пользователь, сокращённый путь в крошках. Нажатие, Enter, Space, Escape, клик снаружи, уход фокуса и возврат фокуса после закрытия проверяются явно.
- Не входит переделка production `_navbar.html.twig`, запуск кабинета, поиск настоящих компаний, реальный вход/выход, платёжные операции и публикация карточек тарифов.
- Разделы 06–15 и 17–28 остаются в аудите незавершёнными. Следующий после этого этап — 06–15 по порядку эталона.

## Задача 2. 16.1 — меню сайта

- [ ] В `_ui_kit_navigation.html.twig` построить шапку высотой 72 px с образцом логотипа, пунктами «Возможности», «Для кого», нейтральной прямой ссылкой и демонстрационными CTA. Выпадающую панель «Возможности» сделать сеткой карточек с правым информационным блоком и нижней полосой; «Для кого» — компактным списком. Все коммерческие подписи обозначить как пример, цену не показывать.
- [ ] Для мобильного образца добавить отдельный макет 56 px шапки, группы навигации, нижний блок действий и семь правил меню сайта. На реальной ширине экрана 320/375 px блок должен помещаться без горизонтального скролла страницы.
- [ ] Кнопки задают `aria-expanded`, `aria-controls`; закрытые панели имеют `hidden`. Прямые ссылки ведут только на существующие публичные URL. Демонстрационные действия без назначения оформлены как неактивные образцы с явной подписью, а не как `href="#"`.
- [ ] Сначала добавить проверку состава в PHPUnit; затем разметку и стили; запустить целевой тест и браузерную проверку открытой/закрытой панели на пяти ширинах.

**Готово, когда:** обе десктопные панели и мобильные группы читаемы, не перекрываются и представлены в тех же смысловых ролях, что в эталоне.

## Задача 3. 16.2 — меню компании и пользователя

- [ ] Создать техническую шапку кабинета высотой 64 px: кнопка выбора демонстрационной организации, индикатор уведомлений, кнопка пользователя. Панель компании содержит подписанное поле поиска по демонстрационному списку, три нейтральных записи и выбранное состояние; панель пользователя — шапку профиля, группированные пункты и нижнее действие.
- [ ] Поиск фильтрует только статический список на странице и показывает текст «Совпадений нет». Выбор компании меняет видимую активную запись, не вызывает сервер и не записывается в storage. Личные данные макета заменить вымышленными образцами с маркировкой «Демо».
- [ ] Добавить пять правил меню кабинета, как в эталоне. Протестировать переключение панелей, поиск без результата, выбор записи и клавиатуру.

**Готово, когда:** состояние обеих панелей различимо визуально и программно, а страница не создаёт впечатление работающего клиентского кабинета.

## Задача 4. 16.3–16.4 — уровни навигации и крошки

- [ ] В 16.3 построить статический образец каркаса: тёмный sidebar с семью строками, активная строка, верхняя строка, вкладки, демонстрационная пагинация; рядом показать нижнюю панель из пяти пунктов и блок правил. Счётчики и суммы заменить нейтральными метками. Статические элементы не делать ложными кнопками.
- [ ] В 16.4 показать большую цепочку крошек, сокращённый путь с раскрытием промежуточных уровней, мобильную родительскую ссылку, вариант на subtle фоне, таблицу параметров, практики и текстовый JSON-LD образец. У вложенного примера использовать заголовок `h3`, сохраняя единственный H1 документа. Production breadcrumbs переиспользовать там, где они поддерживают нужный вариант.
- [ ] Проверить реальные ссылки, `aria-label` у каждой области `nav`, `aria-current="page"` у текущего элемента; кнопка сокращения разворачивает/сворачивает промежуточные элементы и сообщает состояние.
- [ ] Дополнить целевой тест составом 16.3/16.4 и провести браузерную проверку адаптивности.

**Готово, когда:** все четыре подуровня раздела присутствуют и значения примеров не воспринимаются как реальные данные компании.
