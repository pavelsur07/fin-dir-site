# `/ui-kit`: сверка с `Design System.dc.html` — этапы 1–2

Визуальный эталон: `design-system-inbox/Design System.dc.html`. `handoff` использован только для сверки токенов. Базовая страница снята до изменения Twig (`baseline-*`), итоговая — после изменения (`updated-*` и `current-*`). Все изображения и протокол браузера находятся в [ui-kit-audit](ui-kit-audit/). `reference-*` — исходный эталон. Нумерация `*-00.png`…`*-05.png` соответствует разделам; `*-header.png` — шапка. Полные страницы сняты на 320, 375, 768, 1024 и 1440 px.

Состояние снимков: раскрывающиеся элементы закрыты, генератор у исходного эталона и итоговой страницы — S=64, светлый фон. Для итоговой страницы cookie notice принят до съемки отдельных разделов; в полных снимках он скрыт как элемент обычного состояния страницы после согласия. `browser-findings.json` содержит проверку всех 10 сочетаний генератора на каждой ширине. Эталон загружает Inter и Manrope через внешний CSS; сайт загружает локальные Inter и Manrope. Согласованные Onest и Golos Text на сайт не переносились. В браузере нет ошибок JavaScript и отказов загрузки CSS. Не загруженное на снимке изображение футера — следствие `loading="lazy"` вне viewport, опубликованные PNG доступны.

Эталон на 320 и 375 px имеет `scrollWidth=444`, хотя viewport равен 320/375. Это дефект самого макета. Итоговый `/ui-kit` на всех пяти ширинах имеет ширину документа ровно как viewport; узкие внутренние кодовые и конструкционные образцы прокручиваются в своих областях.

## Отдельные решения и ограничения

- Белая верхняя навигация над тёмной шапкой была добавлена страницей `/ui-kit`, отсутствовала в эталоне и удалена только здесь. Техническое меню раздела 16 восстановлено отдельным этапом.
- Для всех пяти ширин `browser-findings.json` фиксирует загрузку страницы, отсутствие ошибок JS и документ без горизонтальной прокрутки. У эталона шрифтовые subset-файлы Inter/Manrope загружены; на сайте Inter/Manrope загружаются локально. Onest/Golos не сравнивались и не добавлялись.
- HEX в Twig используются только как текстовые метки технического каталога. Заливка образцов и стиль страницы исходят из единственного `app.css`. Токен `border-strong` соответствует действующей системе, что сознательно отличается от макета.
- Исторический этап 2 был опубликован отдельно; затем восстановлен раздел 16. После этапа 4 незавершёнными остаются 11–15 и 17–28; изменения 06–10 находятся в отдельной ветке до проверки и решения о публикации.

## Проверка после независимого ревью

Claude Code выполнил read-only review (`/tmp/ui-kit-claude-review.txt`). Подтверждённое замечание high: при S=96 на узком экране образец генератора начинался левее прокручиваемой области. Исправлено `safe center` и уменьшением mobile padding. Повторное измерение на 320/375 px: левая граница образца находится внутри области, содержимое доступно горизонтальной прокруткой. `interaction-findings.jsonl` подтверждает мышь/касание/Space/Enter, отсутствие ошибок и скрытого обрезанного текста на пяти ширинах.

Из замечаний medium исправлены дублирование `.vf-container` (витрина снова использует общий utility) и page-specific перекраска Badge (вариант `accent-solid` объявлен в компоненте). Точные размеры 64/56, 880 и геометрия построения оставлены как осознанное исключение технической витрины: они прямо заданы утверждённым планом и визуальным эталоном; `SITE_RULES.md` уточнён в рамках той же задачи. Примитивные токены используются только в технических образцах эталонных цветов. Уже добавленные пользователем файлы `design-system-inbox/` и посторонний файл в `docs/` не изменялись и не включались в реализацию. Дополнительно исправлены семантика `dl`, подписи PNG, имена ступеней палитры для screen reader, `aria-live` генератора, веса надписей и повторяющаяся разметка логотипа.

`font-faces.json` проверяет реальные записи `FontFaceSet`: на обеих страницах загружены Inter и Manrope; Onest и Golos Text в итоговой странице не загружены. Метод `document.fonts.check()` из первоначального `browser-findings.json` при несуществующем семействе возвращает `true`, поэтому для этой проверки не используется. После финальной правки каждый из 50 наборов параметров генератора повторно сверяется с формулами отдельно.

Финальные проверки: `make assets` и `make assets-check` — успешно; `make ci` — 222 теста, 2543 утверждения, ошибок нет; HTTP `/`, `/ui-kit`, `/ui-kit/sections` — 200. Сборка React, деплой, push и публикация не выполнялись.
