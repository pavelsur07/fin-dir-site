# Обложка статьи и вкладки формы статьи

Риск: высокий — загрузка файлов, миграция, production-конфиг (Production Gate
подтверждён пользователем 2026-10-12: том для загрузок, nginx, Dockerfile php-fpm).

## Решения

- Обложка — PNG ровно 1200×675 (16:9), до 2 МБ. Сервер изображение не меняет
  (GD/Imagick не нужны), проверяет `Assert\Image` по содержимому файла.
- Alt обязателен, если обложка есть. Для публикации обложка не обязательна.
- Без обложки в списке «Газеты» — фиксированная CSS-заглушка 16:9 с постоянным
  текстом. На странице статьи без обложки шапка без картинки.
- Обложка задаётся и при создании, и при редактировании; в одной форме, вкладки
  «Основное», «Текст», «Обложка», «SEO».
- Файлы: `public/uploads/posts/<32 hex>.png`, имя генерирует сервер.
  Production: именованный том `site_uploads` — php-fpm пишет, nginx читает.
- Отступление от PATTERNS §5.2/§17 («адаптер после коммита»): новый файл
  пишется до flush, чтобы база ни на миг не ссылалась на несуществующий файл;
  при любой ошибке он удаляется. Удаление прежнего файла — после коммита.
- В карточках списка картинка декоративная (`alt=""`): карточка — ссылка с
  заголовком. Alt обложки выводится на странице статьи и в предпросмотре.

## Шаги

1. `PostCover` (ValueObject): размеры, лимиты, шаблон имени файла, URL.
   `Post`: колонки `cover_file`, `cover_alt` (nullable), метод `changeCover()`.
   Миграция только добавляет колонки.
2. `PostCoverStorage` (Adapter): сохранить загруженный файл под случайным
   именем, удалить файл по имени (с проверкой шаблона имени).
3. `PostInput`/`PostType`: `coverUpload`, `coverAlt`, `removeCover`;
   `PostCreator`/`PostEditor`: файл пишется до flush, при ошибке удаляется;
   старый файл удаляется после успешного flush.
4. Форма: вкладки (ARIA tablist, клавиатура, без JS — все разделы подряд),
   при ошибке открывается вкладка с первой ошибкой. Скрипт `admin-tabs.js`.
5. Публичный сайт: обложка в карточках и на странице статьи, `og:image`,
   `twitter:image`, JSON-LD `image`; заглушка без обложки.
6. Инфраструктура: nginx `/uploads/` — только `.png`, `nosniff`, кеш на год;
   Dockerfile php-fpm создаёт `/app/public/uploads/posts` от `app`;
   `docker-compose.prod.yml` — том `site_uploads`.

## Проверки

- Unit: `Post::changeCover` (alt обязателен, имя файла по шаблону, снятие).
- Functional: загрузка 1200×675 PNG; неверный размер/тип — 422 без изменений;
  замена удаляет старый файл; снятие обложки; alt без файла; гость → login.
- Functional: публичный список и статья — обложка или заглушка, `og:image`,
  JSON-LD `image`; черновик по-прежнему 404.
- `make assets`, `asset-version` в оба layout, `make ci`, `make ds-check`.
- Независимое ревью перед релизом.

## Перед релизом

- Первый деплой пересоздаст nginx (новый том в конфигурации сервиса `site`):
  короткое окно 404 у Traefik, как при любом изменении сервиса.
- После замены обложки прежний файл сразу удаляется: соцсети, закешировавшие
  старый `og:image`, получат 404 до повторного обхода страницы.
- `make migrate` на production (миграция только добавляет колонки).
- Деплой создаст том `site_uploads`; включить его в резервное копирование
  вместе с базой.
