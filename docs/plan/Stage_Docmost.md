# Docmost — docs.vashfindir.ru

## Цель и границы

Подготовить независимый self-hosted Docmost Community для документации SaaS
на `https://docs.vashfindir.ru`. Пользователь выбрал продукт и поддомен;
подготовка production-конфигурации входит в согласованный объём.
В следующем сообщении пользователь явно разрешил production deploy,
сообщил о настройке DNS и указал email владельца. Релиз выполняется через
PR/CI и штатный GitHub Actions SSH-доступ, поскольку локальный SSH-ключ
этого хоста сервер не принимает.

Docmost владеет только своей документацией, пользователями и вложениями.
Он не подключается к данным и authentication Symfony. Отдельный готовый
продукт выбран пользователем вместо разработки собственной wiki.

## Решение

- `docker-compose.docmost.yml`, project `vf-docmost`: приложение, PostgreSQL
  и Redis; закреплённые версии и digests, healthchecks и постоянные volumes.
- Только приложение присоединяется к общей внешней сети `traefik_web`.
  Существующие Symfony, conwix и конфигурация Traefik не меняются.
- Host rule строго `docs.vashfindir.ru`, HTTP → HTTPS, resolver `le`.
- Первый запуск закрыт от Traefik, доступен через loopback и SSH tunnel.
  После создания владельца включается публичная маршрутизация.
- Секреты в игнорируемом `docmost/.env`; образец содержит пустые значения.
- Makefile — команды проверки, запуска и smoke; отдельный ручной deploy
  workflow. CI проверяет только одноразовое окружение на синтетических данных.
- Ручной workflow умеет создать закрытый env и первичного владельца через
  stdin с временным GitHub secret; публикация включается отдельным input
  только после setup. Существующие пользователи/пароли не перезаписываются.

## Риск: высокий

Production routing, доступ к внутренней документации и сохранность данных.
Критичные условия: не публиковать пустую установку, не открывать БД/Redis,
не выводить секреты, не менять соседние стеки; сохранять данные при
пересоздании контейнеров. До обновлений нужны резервные копии БД, файлов
и APP_SECRET. Автоматические миграции Docmost требуют проверки обновления;
откат только образа после миграций небезопасен.

## Шаги и критерии приёмки

1. Добавить отдельный Compose, шаблон env и эксплуатационную инструкцию.
2. Добавить Make-команды, изолированный smoke и CI/manual deployment.
3. Проверить Compose без секретов, отказ без обязательных переменных,
   изоляцию сетей/портов, закрытый bootstrap и публичные метки после включения.
4. Запустить настоящий Docmost в отдельном временном Compose project:
   health, HTTP, создание тестового владельца, отказ анонимному запросу,
   сохранение workspace и вложений после пересоздания контейнеров.
5. Self-review и обязательное независимое read-only ревью всего diff.

Команды: `make docmost-check`, `make docmost-smoke`, `git diff --check`.
Результаты и ограничения дописываются ниже после выполнения.

## Production prerequisites

DNS A `docs.vashfindir.ru` → сервер общего Traefik. При проверке из текущей
среды 10.11.2026 IPv4 запись не найдена; повторить перед публикацией.
Секреты, первичный владелец и SMTP настраиваются на сервере. Деплой и
выпуск публичного TLS не считаются проверенными локальным smoke.

## Результат проверки

- Реализованы отдельный стек, генератор закрытого env, Make-команды,
  документация, PR CI и ручной deploy с проверкой точного commit SHA.
- `make docmost-check` — успешно: обязательные секреты, отказ от перезаписи
  env, права `0600`, закрытый bootstrap, правила маршрутов, сети и volumes.
- Финальный `make docmost-smoke` — успешно на реальных закреплённых images:
  health/UI; запрет публикации пустой установки; владелец; `403` повторного
  setup; `401` анонимного API; сохранение workspace, входа и файла при полном
  пересоздании контейнеров; валидные архивы из Make-команд backup.
- Временный project и его volumes удалены после проверки.
- YAML workflow, shell-сценарии и сформированный Make dry-run deployment
  проверены синтаксически. `git diff --check` и проверка новых файлов — успешно.
- Self-review и независимое read-only ревью завершены без существенных
  замечаний. Временный контейнер файлового backup явно исключён из Traefik.
- Production DNS/TLS, реальный SSH deploy, SMTP, совместное редактирование
  в браузерах и восстановление backup не проверены. GitHub CI подготовлен,
  но до разрешения деплоя удалённый workflow не запускался.

## Развёртывание после разрешения пользователя

- Добавлен автоматический bootstrap через stdin и временный GitHub secret.
  Локальный smoke повторно пройден: отсутствие credentials и попытка
  публикации пустой установки отклоняются, повторный bootstrap не меняет
  пользователя, вход созданным владельцем работает, `.env` остаётся `0600`.
- Подготовлен релиз через `feat/docmost-service` → PR → обязательный CI →
  `master` → ручной `Deploy docs.vashfindir.ru`.
- Пароль владельца создаётся случайно, хранится вне Git; после bootstrap
  временный repository secret удаляется. Значения не выводятся в логи.
