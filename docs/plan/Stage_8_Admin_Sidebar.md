# Рефакторинг /admin: сайдбар слева, рабочая зона на всю ширину

## Контекст

Сейчас навигация админки — тёмная шапка сверху (`site/templates/admin/layout.html.twig`):
бренд, «Публикации», «Обращения», логин и «Выйти». Контент ограничен шириной 960px и стоит
по центру. Разделов становится больше, поэтому пользователь просит:

- **меню в сайдбаре слева**;
- **рабочую зону на 100% ширины** экрана;
- **на телефоне** — верхнюю полосу с кнопкой «Меню»;
- **счётчик новых обращений** у пункта «Обращения»;
- сворачивать сайдбар **не нужно**.

Админка остаётся временной Twig-админкой со своим inline-CSS: исключение из AGENTS.md §8,
Stage 4. Публичный сайт, `SITE_RULES.md` и Tailwind это не затрагивает.

## Решения

**Разметка — один layout, меню — один список.**
- `admin/layout.html.twig` получает блок `page` с каркасом:
  - `aside.sidebar`, фиксированный слева, ширина 240px, высота 100vh, прокручивается сам по себе;
  - `div.workspace` на всю оставшуюся ширину, внутри `main` с flash-сообщениями и блоком `body`.
- Пункты меню задаются одним массивом в layout `{label, route, active_prefix}`: Панель → `admin_dashboard`, Публикации → `admin_post*`, Обращения → `admin_lead*`. Новый раздел добавляется одной строкой.
- Активный пункт получает `aria-current="page"` и подсветку. Для «Публикаций» это список, редактирование и предпросмотр, как сейчас.
- Внизу сайдбара — имя пользователя и «Выйти» (POST + CSRF, как сейчас).
- Логин переопределяет `page`: карточка по центру, без сайдбара. Блок `header` убирается.

**Мобильная версия (до 900px) — без JavaScript.**
- Сайдбар скрыт, сверху полоса: бренд и `<details><summary>Меню</summary>…</details>`.
- Раскрытый список — тот же `admin/_nav.html.twig`, что в сайдбаре: одна разметка, два места.
- На каждой ширине видна одна копия меню, вторая скрыта через `display: none`, поэтому для экранных дикторов меню не дублируется.

**Рабочая зона.**
- Ограничение `max-width: 960px` снимается, отступы 24px (на мобильных 16px).
- Таблицы и списки растягиваются на всю ширину.
- Формы (`form.panel`), карточка обращения (`.details`) и предпросмотр статьи оставляют ширину для чтения — `max-width` около 960px, прижаты влево. Текстовые поля во всю ширину экрана читать тяжело.

**Счётчик новых обращений — через Controller → Query, без запросов из Twig (AGENTS §7).**
- `Lead/Query/NewLeadCount/NewLeadCountQuery::count()` — `COUNT` по `status = 'new'` (индекс `lead_lead_status_idx` уже есть). Спам и обращения в работе не считаются.
- `Lead/Controller/Admin/LeadCounterController` — фрагмент без маршрута, `#[IsGranted('ROLE_ADMIN')]`, рендерит `admin/leads/_counter.html.twig`:
  - при 0 — пустая строка;
  - иначе `<span class="count" aria-label="новых: N">N</span>`.
- Layout вызывает его **один раз** через `render(controller(...))` и передаёт готовую строку в оба места меню. Если inline-фрагменты не заработают без `framework.fragments`, включаю их в `framework.yaml`, путь `/_fragment` наружу не нужен.

## Файлы

- `site/templates/admin/layout.html.twig` — каркас, CSS сайдбара, мобильной полосы и рабочей зоны, массив меню.
- `site/templates/admin/_nav.html.twig` — новый: пункты меню, счётчик, пользователь и «Выйти».
- `site/templates/admin/login.html.twig` — переопределение `page` вместо `header`.
- `site/templates/admin/leads/_counter.html.twig` — новый.
- `site/src/Lead/Query/NewLeadCount/NewLeadCountQuery.php`, `site/src/Lead/Controller/Admin/LeadCounterController.php` — новые.
- `site/templates/admin/dashboard.html.twig` — без изменений (ссылки дублируют меню, это нормально).
- Шаблоны публикаций и обращений не меняются: классы `.toolbar`, `.panel`, `.table` остаются.

## Проверка

`make ci`; Playwright-сценарий; вручную в dev: пункты меню ведут куда нужно, счётчик меняется при смене статуса обращения.
