# Hero и обновление безопасности Symfony

## Цель и приёмка

Опубликовать согласованный текст Hero, обновив уязвимые зависимости Symfony
в пределах существующей ветки 7.4. Composer audit не обнаруживает уязвимостей,
CI и production smoke проходят, PR #240 слит в master, deploy завершён успешно,
главная production-страница отдаёт новый заголовок и подпись.

## Риск и границы

Повышенный риск: общие HTTP- и security-компоненты могут изменить обработку
маршрутов, авторизации и сессий. Не изменять security-конфигурацию, публичные
URL, схему данных, Dockerfiles или workflow. Сохранить несвязанные локальные
документы. Пользователь разрешил обновление зависимостей, merge и deploy.

## Шаги и проверки

1. Через make update обновить Symfony 7.4 с минимальными изменениями остальных
   пакетов; проверить diff composer.lock и composer validate/audit.
2. Запустить make ci и проверки production images в GitHub Actions; проверить
   тесты входа, CSRF, logout и сессий в make php-production-smoke.
3. Провести self-review и независимое read-only ревью полного diff.
4. После успешного CI слить PR с проверкой ожидаемого head SHA, дождаться
   штатного deploy workflow и проверить HTTP 200 и новый Hero в production.

Новых архитектурных паттернов, миграций и технологий не требуется.
