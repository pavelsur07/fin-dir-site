# Stage: всплывающее окно записи на разбор (lead modal)

## Цель

Добавить на маркетинговые страницы всплывающее окно «Запишитесь на бесплатный разбор ваших цифр»
по макету `docs/plan/lead-modal/`. Окно открывается автоматически по правилам показа и по кнопкам.
Заявка уходит в существующий сценарий `POST /lead` как новая форма `popup`.

Риск: обычный (UI + новая запись каталога форм; контракт `/lead`, CSRF и схема БД не меняются).

### Состав окна

Десктоп (≥ lg): карточка 960px, две колонки 1.3fr / 1fr, скругление `rounded-xl` или ближайший токен темы,
затемнение фона navy с прозрачностью.

Левая колонка — синяя панель (`bg-accent-fill`, тёмная область `dark`), наклонные декоративные полосы
как в `_hero` (`-skew-x-12`, `aria-hidden`):

- логотип на тёмном: `components/_logo` с `dark: true, s: 28, lazy: true`;
- чипы: «Бесплатно», «45 минут», «Онлайн»;
- заголовок H2 (не H1 — H1 на странице уже есть): «Покажем, где ваш бизнес теряет прибыль»;
- список с иконкой `check`:
  - «Разберём движение денег и прибыль по направлениям»
  - «Покажем кабинет на примере ваших цифр»
  - «Для селлеров — маржа до CM3 по товарам»
- внизу два факта: «С 2015 — в финансах бизнеса», «230+ — компаний» (те же данные, что в `_trust_strip`; взять из того же источника, не дублировать строки);
- фото Павла справа снизу: `/assets/people/pavel-novikov-800.{avif,webp}` + `pavel-novikov.png`, как в `_hero`, `loading="lazy"`.

Правая колонка — форма:

- заголовок формы (p, не heading): «Запишитесь на бесплатный разбор ваших цифр»;
- «Как вас зовут» — `name`;
- «Как с вами связаться» — переключатель `contact_type` Телефон / Telegram (`components/_form_segmented`, как в форме `excursion`) и одно поле `contact` с `data-vf-contact-input` (placeholder `+7 900 000-00-00` / `@username` меняет существующий JS);
- согласие на обработку ПД — `components/_form_checkbox`, не отмечено по умолчанию, тот же текст и ссылка, что в `_lead_form`;
- кнопка primary во всю ширину: «Записаться на разбор»;
- текстовая кнопка «Не сейчас» (закрывает окно);
- кнопка-крестик в правом верхнем углу, `aria-label="Закрыть"`.

Почты нет. Вопросов о роли и обороте нет.

Успех: поля скрываются, показывается блок с иконкой (success), «Заявка отправлена», «Свяжемся в рабочее время и договоримся о времени разбора.»
и secondary-кнопка «Закрыть». Ошибки — существующие `data-vf-lead-error` и ошибки под полями.

Мобильный (< lg): нижняя панель на всю ширину, скругление только сверху, высота не больше ~94% экрана с прокруткой
внутри; сверху синяя часть (чипы, H2, список, фото справа, без логотипа и фактов), ниже форма. Индикатор-«ручка» декоративный.

## Поведение

### Правила автопоказа

1. Прокрутка: посетитель прошёл ≥ 55% высоты страницы.
2. Уход (только устройства с `(hover: hover) and (pointer: fine)`): курсор покинул окно через верхний край (`mouseout` с `relatedTarget === null` и `clientY <= 0`).
3. Запасной таймер: 45 секунд активного пребывания на странице (вкладка видима).

Срабатывает первое из правил; после показа остальные снимаются.

Не показывать автоматически, если:

- окно уже показывалось этому браузеру за последние 7 дней (ключ в `localStorage`, например `vf-lead-modal` → `{shownAt, submittedAt}`; чтение и запись в `try/catch`, при ошибке — не показывать);
- посетитель уже отправил любую форму заявки с этого браузера (ставить `submittedAt` при ответе 201 любой `data-vf-lead-form`); такой посетитель автоматически окно больше не видит;
- открыто мобильное меню (`data-vf-menu-dialog` открыт) или ещё не сделан выбор в баннере cookie;
- фокус в поле ввода на странице (человек заполняет форму);
- форма заявки внизу страницы (`#lead-form`) в зоне видимости — показывать окно поверх формы бессмысленно;
- страница не маркетинговая (см. ниже).

### Открытие по кнопке

- Любой элемент с `data-vf-lead-modal-open` открывает окно (без проверок частоты и правил выше).
- Это ссылки `href="#lead-form"`: без JS или если окно не инициализировалось, ссылка ведёт к форме внизу страницы (прогрессивное улучшение). Скрипт делает `preventDefault` только когда окно реально откроется.
- На странице без формы внизу ссылка ведёт на `/#lead-form` — то же поведение.
- Ссылка с `?modal=lead` в адресе открывает окно сразу после загрузки (для рассылок и рекламы); после открытия параметр убрать из адреса через `history.replaceState`, остальные параметры (utm) сохранить.
- `components/_button` сейчас не принимает data-атрибуты: добавить необязательный аргумент `attrs` (map атрибут → значение), по аналогии с form-компонентами. Существующие вызовы не меняются.

Подключить `data-vf-lead-modal-open` к кнопкам:

- главная: hero «Обсудить ваши задачи», CTA во вкладках «Что входит» и «Преимущества», «Интеграции», FAQ «Задать вопрос»;
- кнопка в шапке (`_navbar` cta), десктоп и мобильное меню (в мобильном меню: сначала закрыть меню, потом открыть окно);
- CTA на `service_financial_director`, `service_financial_model`, `services`.

Тексты кнопок не менять.

### Закрытие и доступность

- Реализация на нативном `<dialog>` + `showModal()`: фокус внутри окна, `Esc` закрывает, фон инертен.
- Закрывают: крестик, «Не сейчас», `Esc`, клик по затемнению вне карточки, «Закрыть» после успеха.
- При открытии фокус на поле «Как вас зовут»; после закрытия фокус возвращается на кнопку, которая открыла окно (при автопоказе — без перемещения).
- Прокрутка страницы под окном заблокирована, пока окно открыто (классом на `html`/`body` из темы, не JS-стилем).
- Анимация появления — только `motion-safe:`; при `prefers-reduced-motion` окно появляется без анимации.
- Классы, которые переключает JS, должны быть полными строками в исходниках, которые сканирует Tailwind. JS не задаёт CSS-свойства.
- Нет горизонтальной прокрутки на 320, 375, 768, 1024, 1440.

- `lead_form_submit` — как сейчас, при 201 (не менять);

## Сервер

- `LeadFormCatalog`: новая форма `'popup' => new LeadFormDefinition('popup', 'Всплывающее окно — разбор')` без вопросов. Миграция не нужна (комментарий в каталоге).
- Проверить, что `contact_type` работает для формы без вопросов (сейчас переключатель показывается только для `excursion`: в шаблоне это `with_contact_type = definition.key == 'excursion'` — не завязывать окно на эту строку, передать явный аргумент).
- Контроллер `POST /lead`, DTO, CSRF (`lead_submit` stateless), уведомления — без изменений.
- Анонимный GET не стартует сессию (окно рендерится в той же странице, CSRF stateless) — проверить существующим тестом/добавить проверку отсутствия `Set-Cookie` сессии на главной с окном.

## Структура

- `site/templates/website/sections/_lead_modal.html.twig` — окно; аргументы через `with … only`.
- Поля формы не копировать из `_lead_form`: вынести общую часть формы (hidden-поля, honeypot, имя, контакт, согласие, кнопка, success/error) в компонент, например `components/_lead_form_body.html.twig`, и использовать его в `_lead_form` и в окне. Разметка существующей формы на страницах не должна измениться (проверить тестами и скриншотом). ID полей уникальны: префикс `lead-modal-`.
- Включение окна: блок `lead_modal` в `website/layouts/base.html.twig`, по умолчанию пустой; маркетинговые страницы (`pages/marketing/*`, кроме `docs_stub`) включают окно. Не включать на `legal/`, `lead/`, `errors/`, `publication/`.
- `site/assets/scripts/website/lead-modal.js` — правила показа, открытие/закрытие, хранение в `localStorage`. Подключить в layout с `defer` и версией `vf_asset_version`.
- Успех/ошибка формы: если существующий обработчик в `navigation.js` нужно уведомить окно, добавить в него одно событие `vf:lead-submitted` на форме (detail: `{formKey}`) при 201. Логику отправки не дублировать.
- Ширина карточки 960px: в `shared/vf-palette.css` (`@theme`) добавить токен `--container-modal-xl: 960px` → класс `max-w-modal-xl`. Других новых токенов не вводить; произвольные значения `[...]` запрещены.

## Тесты

- Functional: на главной есть окно (`data-vf-section="lead-modal"`) с формой `popup`, CSRF-токеном, полями `name`, `contact_type`, `contact`, согласием; на `/privacy` и на 404 окна нет.
- Functional: `POST /lead` с `form=popup` и телефоном → 201; с Telegram → 201; без согласия/с неверным контактом → 422 с ошибками полей.
- Существующие тесты форм и `MarketingSectionsTest` проходят без изменения ожиданий по `_lead_form`.
- JS-поведение (правила показа) проверить вручную в браузере по чек-листу ниже; e2e не добавлять.

Ручная проверка:

1. Новый посетитель: окно появляется после ~55% прокрутки; повторная загрузка — не появляется (7 дней).
2. Очистить `localStorage`: уход курсором за верх окна на десктопе — окно появляется.
3. Кнопка hero и кнопка в шапке открывают окно всегда; фокус возвращается на кнопку после закрытия.
4. `/?modal=lead&utm_source=test` — окно открыто, в адресе остался только `utm_source`.
5. Отправка из окна: заявка в админке с формой «Всплывающее окно — разбор», уведомление в Telegram; после этого автопоказ не срабатывает.
6. Мобильное меню открыто — автопоказ не перекрывает его; кнопка в мобильном меню закрывает меню и открывает окно.
7. Esc, клик по фону, «Не сейчас», крестик — закрывают. Tab не выходит за пределы окна.
8. `prefers-reduced-motion: reduce` — без анимации. 320/375/768/1024/1440 — без горизонтальной прокрутки.
