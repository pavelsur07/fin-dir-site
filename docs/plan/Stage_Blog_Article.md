# Stage: страница статьи «Газеты» по новому макету + формы захвата как секции

## Цель

Перевести страницу статьи (`/gazeta/{slug}`, `pages/publication/blog_post.html.twig`) на макет
`docs/plan/blog-article/`. Все формы захвата оформить отдельными переиспользуемыми секциями,
тексты которых задаются в админке у каждой статьи, с общими значениями по умолчанию.
Список статей (`/gazeta`) в этот этап не входит.

Риск: обычный. Есть аддитивная миграция (только новые nullable-колонки), контракт `POST /lead`,
CSRF и существующие формы не меняются. Production Gate не требуется.

без произвольных значений в квадратных скобках, без JS, задающего CSS-свойства.
Текст статьи в макете — пример контента; в шаблон ничего из него не хардкодить.

## Что уже есть и сохраняется

- Оглавление с прогрессом и активным пунктом (`article-toc.js`, `_article_toc_list`), липкая панель, аккордеон ниже lg — оставить, привести внешний вид к макету (полоса прогресса, счётчик «N из M», подсветка активного пункта фоном `cobalt-50`/`accent`).
- Врезки рендерера («Коротко», «Важно», «Совет»), таблицы, якоря H2, FAQ, JSON-LD, обложка поста, canonical, кеш `max-age=300`.
- Форма вопроса `sections/_article_question` (форма `consultation`) и поле `formTitle` в админке.

## Шапка статьи

Одна колонка, сверху вниз:

1. Крошки (как сейчас).
2. Чип рубрики (`post.rubric.label`), если рубрика есть. В `PublicPostView` добавить `rubric`.
3. H1 во всю ширину, но не шире `max-w-title` (≈ 900px; если токена такой ширины нет — ближайший существующий, новый токен только при необходимости и с обоснованием). `text-balance`, `hyphens-auto`.
4. Лид (`excerpt`) — ширина колонки текста (`max-w-measure`), `type-t4`.
5. Автор: фото 48–52px (круг), «Имя · роль», вторая строка «Проверила/Проверил Имя, роль» — если задан проверяющий. Ссылка с имени на блок автора внизу.
6. Мета: дата, «Обновлено …» (если было), «N минут». На мобильном «Обновлено» скрыть, чтобы строка не переносилась.

Обложка — под шапкой, в колонке статьи (`max-w-measure`), `aspect-video`, без кадрирования (`object-contain` или точное 16:9), `rounded-lg`. Оглавление в панели начинается на уровне обложки.
Без обложки блок не выводится (как сейчас).

## Тело статьи

Новые виды врезок в `MarkdownRenderer` (тем же механизмом меток в цитате, без HTML в Markdown):

| Метка в начале цитаты | Вид | Оформление |
|---|---|---|
| `**Пример**` (`**Пример: конец месяца**`) | `example` | белая карточка с рамкой, подпись капсом `t7`, строки «название — значение» из списка: числа `tabular-nums`, не переносятся |
| `**Как это отражается на решении**` | `impact` | `surface-muted`, рамка, заголовок с иконкой info цвета `accent` |

Существующие виды и их метки не менять. Цитата без метки остаётся как сейчас.
Цветные плашки «Обязательные / Необязательные / Переносимые» и график по неделям из макета — пример возможностей, в Markdown не поддерживаются и в этот этап не входят.

## Формы захвата — отдельные секции

Ответ на вопрос «что делать с формами, оформленными под каждую статью»: **отдельной формы под каждую статью не делать.**
Делается четыре типа секций. У каждой статьи в админке можно переопределить **тексты** секций;
пустые поля берут значения по умолчанию из конфигурации (по рубрике, затем общие). Код и шаблоны под конкретную статью не создаются.

| # | Секция | Где | Что делает | Тексты статьи (админка) | Форма / цель |
|---|---|---|---|---|---|
| 1 | `sections/_article_cta_inline` | В теле статьи (см. размещение ниже), один раз | Синяя карточка: заголовок, текст, кнопка «Записаться на разбор», фото Павла справа | `ctaTitle` (≤ 80), `ctaText` (≤ 160) | Кнопка открывает окно записи (`data-vf-lead-modal-open`, href `#article-final`), форма `popup` |
| 2 | `sections/_article_question` (есть) | Панель справа (lg+), под статьёй ниже lg | Форма вопроса | `formTitle` (есть) | `consultation`, без изменений контракта; поле «Телефон, email или Telegram» оставить |
| 3 | `sections/_article_lead_magnet` | После вывода статьи, перед блоком «Поделиться». Только если у статьи выбран материал | Карточка материала (иконка документа, название, «PDF, 2 страницы»), кнопка «Получить». По кнопке раскрывается короткая форма: имя, Телефон/Telegram, согласие. После 201 — ссылка на файл и текст «Готово, файл ниже» | `leadMagnet` (выбор из каталога) | новая форма `lead_magnet`; цель Метрики `lead_magnet_submit`; клик по ссылке файла — `lead_magnet_download` |
| 4 | `sections/_article_final_form` | После «Ещё по теме», перед футером, `id="article-final"` | Синяя секция: чипы «Бесплатно · 45 минут · Онлайн», заголовок, текст, факты `vf_trust_facts`, форма: имя, Телефон/Telegram, согласие, «Записаться на разбор» | `finalTitle` (≤ 80), `finalText` (≤ 200) | новая форма `article`; цель `lead_form_submit` (как у всех форм) |

Правила для всех секций:

- Поля и отправка — общий компонент формы (`components/_lead_form_body` из этапа окна, если он есть; иначе вынести, не копируя разметку). `POST /lead`, CSRF `lead_submit` stateless, honeypot, `submission_id`, `page_url` — без изменений. Из `page_url` в CRM видно, с какой статьи заявка.
- `LeadFormCatalog`: добавить `'article' => 'Статья — разбор'` и `'lead_magnet' => 'Статья — материал'` без вопросов. Миграция для форм не нужна.
- ID полей уникальны на странице (две формы `consultation` уже есть: префиксы `article-question-panel/bottom`; новым секциям — свои префиксы).
- Окно записи (`_lead_modal`) подключить на странице статьи **без автопоказа**: только открытие кнопками. Добавить в секцию окна необязательный аргумент `auto` (по умолчанию `true`), при `false` — атрибут, по которому `lead-modal.js` не включает правила автопоказа. На маркетинговых страницах поведение не меняется.
- Не больше одной inline-карточки и одного материала на статью.

### Размещение inline-карточки

- Автор ставит её цитатой с меткой `> **Разбор**` в нужном месте Markdown; текст цитаты после метки игнорируется (тексты берутся из полей статьи/по умолчанию).
- Если метки нет: автоматически перед третьим H2, если в статье ≥ 4 H2; иначе не выводится.
- Технически: рендерер отмечает место, `RenderedArticle` отдаёт тело двумя частями (до и после места), шаблон выводит между ними секцию. Маркер в HTML-строке, который можно подделать из Markdown, не использовать.

### Значения по умолчанию

`config/packages/twig.yaml` (или параметры, как `vf.article_form.*`) — `vf_article_capture`:

### Каталог материалов

Конфигурация `vf_lead_magnets` (ключ → `title`, `meta`, `file`), файлы в `site/public/assets/files/`.
Загрузку файлов через админку в этот этап не делать. Первый материал: `cashflow-checklist` — «Чек-лист самопроверки платёжного календаря», файл владелец положит сам; до этого — PDF-заглушка с пометкой «черновик».
В админке у статьи — выпадающий список ключей каталога (пусто — нет материала). Неизвестный ключ в БД → блок не выводится, без ошибки.

## Автор и проверяющий

- `vf_team.people` дополнить `key` (латиница) и `bio` (для Павла: «28 лет в бизнесе, с 2015 года — в финансах малого и среднего бизнеса. Основал «Бухгалтерский аутсорсинг»…» — текст из макета; для остальных можно пусто).
- `Post`: `authorKey`, `reviewerKey` (nullable). Админка: два выпадающих списка из `vf_team`. Пусто — «Редакция Ваш Финдир» без фото (как сейчас).
- Блок «Об авторе» внизу статьи (фото, «Автор», имя и роль, `bio`, ссылка на Telegram-канал из существующей конфигурации ссылок). Без автора блок не выводится.
- JSON-LD: при наличии автора `author` = `Person` (name, jobTitle), `publisher` — организация, как сейчас.

## «Поделиться» и «Ещё по теме»

- Строка «Отправьте коллеге или бухгалтеру»: ссылка Telegram (`https://t.me/share/url?url=…&text=…`, `target=_blank rel=noopener`) и кнопка «Скопировать ссылку» (Clipboard API; при успехе текст кнопки на 2 с «Ссылка скопирована» через переключение `hidden` у двух span, `aria-live`). Без JS кнопку не показывать. Иконки Lucide `send`, `link`.
- «Ещё по теме»: карточки с обложкой 16:9, рубрикой, заголовком, датой и временем чтения (данные `PublicPostListItem` уже есть), 3 колонки с lg, 1 колонка на мобильном. Без обложки — существующая заглушка списка. Ссылка «Все статьи Газеты →». Правило «не меньше двух материалов» сохранить.

## Данные и миграция

Одна Doctrine migration, только `ADD COLUMN … NULL` в `publication_post`:
`author_key`, `reviewer_key` (varchar 32), `cta_title` (80), `cta_text` (160), `final_title` (80), `final_text` (200), `lead_magnet` (32).
Поведение через методы сущности (`edit()` расширить), `PostInput`/`PostType`, валидация длины; `PostEditData` и `PublicPostView` — новые поля.
Существующие статьи без значений выглядят по значениям по умолчанию.

## Обложки

Обложки по-прежнему загружаются в админке (1200×675). Образец оформления — `blog-article/covers/`:
синий / светлый / тёмный фон с наклонными полосами, чип рубрики, заголовок 64px белым или navy, логотип внизу слева,
справа фото команды или экран сервиса. Текст на обложке допустим, потому что обложка не кадрируется.

## Тесты

- Functional `GET /gazeta/{slug}`:
  - без полей захвата: inline-карточка по умолчанию стоит перед третьим H2 при ≥ 4 H2 и отсутствует при < 4; финальная форма с текстами по рубрике; материала нет; окно записи есть, автопоказ выключен (атрибут);
  - с `> **Разбор**`: карточка на месте метки, в тексте метки нет, вторая автоматически не появляется;
  - с полями статьи: тексты из статьи; с материалом — блок материала и форма `lead_magnet`; неизвестный ключ материала — блока нет, 200;
  - автор/проверяющий: строка в шапке, блок «Об авторе», `Person` в JSON-LD; без автора — «Редакция Ваш Финдир», блока нет.
- Unit `MarkdownRenderer`: метки «Пример» и «Как это отражается на решении» дают `example`/`impact`; метка «Разбор» даёт место для карточки; прежние виды не изменились.
- Functional `POST /lead`: `form=article` и `form=lead_magnet` с телефоном и Telegram → 201; без согласия → 422.
- Миграция применяется на БД с существующими статьями; статьи открываются.
- Анонимный GET статьи не стартует сессию.

Ручная проверка: 320/375/768/1024/1366/1440 без горизонтальной прокрутки; заголовок на 1366 — не больше 3 строк; оглавление подсвечивает раздел при прокрутке; inline-кнопка открывает окно, фокус возвращается; форма материала показывает ссылку после отправки; «Скопировать ссылку» работает и без JS скрыта; `prefers-reduced-motion`.
