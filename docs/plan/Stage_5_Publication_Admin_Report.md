# Stage 5 — Publication: отчёт

## Что реализовано

Раздел админки `/admin/posts`, где контент-менеджер ведёт статьи блога:
- **Список:** фильтр по статусу, сортировка по дате изменения, дате публикации или заголовку, по 20 на страницу.
- **Создание и редактирование:** текст в Markdown, анонс, SEO title и description, slug.
- **Предпросмотр** в Markdown с `noindex`.
- **Переходы статуса:** опубликовать, снять с публикации, в архив, вернуть в черновики. Каждый переход — отдельный POST с CSRF-токеном.

Публичная часть (`/gazeta`) не менялась, это Stage 6.

## Решения

- **Модуль `Publication`:**
  - Entity `Post` (таблица `publication_post`) с правилами переходов статуса;
  - Application Services с одним `flush()` на сценарий;
  - чтение через Query, DTO-проекции и Pagerfanta.
- **Статусы и повторы.** Статусы: DRAFT, PUBLISHED, ARCHIVED. Повторный переход в текущий статус ничего не делает, поэтому повторный POST безопасен. `unpublish` из архива запрещён: для этого есть `restore`. Эту ошибку нашёл unit-тест.
- **`publishedAt`** — дата первой публикации. После неё slug больше не меняется, поэтому таблица 301-редиректов не нужна.
- **Оптимистичная блокировка** через `#[Version]`:
  - устаревшая форма получает 422 с ошибкой «статью изменили в другом окне»;
  - гонка при смене статуса даёт 409;
  - версия на редактировании обязательна.
- **Slug:**
  - транслитерация своей таблицей: в образах нет `ext-intl`, и `AsciiSlugger` кириллицу не транслитерирует;
  - если slug сгенерирован из заголовка и уже занят, добавляется суффикс `-2`, `-3`… в пределах 150 символов;
  - если slug задан вручную и занят, это ошибка у поля формы.
- **Markdown** рендерит `league/commonmark` (GFM). HTML из текста вырезается, небезопасные ссылки отбрасываются, поэтому `|raw` безопасен.
- **Общий `DomainExceptionListener`:** исключения, помеченные `NotFound`, превращаются в 404, помеченные `Conflict` — в 409. Ожидаемые ошибки ввода (занятый или заблокированный slug, устаревшая версия) контроллеры create и edit показывают прямо в форме. Это осознанное отступление от PATTERNS §6: пользователю лучше видеть ошибку у поля, чем страницу 409.
- **CSRF переходов** проверяется явно через `isCsrfTokenValid`. Атрибут `#[IsCsrfTokenValid]` бросает `AuthenticationException`, и firewall отвечал бы залогиненному админу редиректом на логин вместо 403.
- **Рецепт `symfony/form`** добавлял `csrf.yaml` со stateless CSRF для входа и выхода. Файл удалён: иначе это молча поменяло бы защиту из Stage 4.
- **Deptrac:** слои `ValueObject`, `Exception`, `DTO`, `Form`, `EventListener`, `Adapter` и vendor-слои `Pagerfanta`, `CommonMark`, `Clock`. Нарушений 0, непокрытых зависимостей 0.
- **Тестовая БД `site_test`:**
  - в `doctrine.yaml` для test-окружения задан `dbname_suffix`;
  - Makefile получил цель `make test-db`, и `make test` вызывает её сам;
  - `dama/doctrine-test-bundle` откатывает каждый тест. Официально он заявляет PHPUnit ≤ 12, но с PHPUnit 13 работает: повторный прогон оставляет `site_test` пустой;
  - в CI добавлены postgres service и шаг подготовки БД.

## Ревью

- **Self-review:**
  - найден и исправлен CRLF в Makefile, который мой скрипт переписал в LF;
  - проверено, что атрибуты `aria-current` рендерятся корректно.
- **Claude Code review** (первый проход): blocker и high нет, найдено 3 medium, все исправлены:
  - гонка при смене статуса давала 500 → теперь 409;
  - slug длиннее колонки при коллизии давал 500 → суффикс укладывается в 150 символов, в Entity добавлены проверки длины;
  - защиту от конкурентной правки можно было обойти → версия на редактировании обязательна.

  Low-замечания тоже исправлены:
  - `slugExists` через `count()`;
  - приоритет listener;
  - инвариант body у опубликованной статьи;
  - адаптер перенесён в каталог `Adapter\`;
  - подсказка к slug на странице редактирования;
  - недостающие тесты.
- **Повторное ревью исправлений:** blocker, high и medium нет. Low исправлены:
  - порядок проверок slug;
  - общая константа `PostTitle::MAX_LENGTH`;
  - комментарий о закрытом EntityManager;
  - лишняя проверка в тесте.
- **Не исправлялось, принято осознанно:**
  - Уровень логов `warning` для ожидаемых доменных ошибок (PATTERNS §12) не настроен: логгера (monolog) в проекте нет. Настроить, когда он появится.
  - Предпросмотр вызывает Query и Adapter в одном контроллере. Это разрешено в deptrac как `Controller → Adapter`; отдельный Query ради одного вызова был бы лишним.
  - Кнопки смены статуса не передают версию: «Опубликовать» на устаревшей странице опубликует текущий текст статьи. Для одного контент-менеджера это приемлемо.
  - Даты хранятся как `TIMESTAMP WITHOUT TIME ZONE`, поэтому таймзона PHP в контейнерах должна совпадать. В dev у fpm и cli UTC: это значение PHP по умолчанию, ini его не задаёт. В prod-образах отдельно не проверялось.
