# Ежедневная очистка просроченных заявок

## Цель и выбор

Запускать существующую команду `app:lead:purge-expired` на vashfindir.ru ежедневно в 03:00 по Москве. Изменение затрагивает production и необратимое удаление заявок. Бизнес-логика очистки остаётся в Symfony.

Сервис `site-scheduler` в Compose использует BusyBox crond из Alpine CLI-образа. Compose передаёт ему тот же образ и окружение, что и `site-php-cli`. Для systemd timer понадобилось бы отдельно настраивать на хосте запуск Compose с production-окружением, которое сейчас доступно в SSH-сеансе деплоя.

Команда и миграция журнала приходят из [PR #268](https://github.com/pavelsur07/fin-dir-site/pull/268). Пока этот PR открыт, ветка планировщика основана на `feature/legal-compliance`. После его слияния PR планировщика следует направить в `master` и проверить состав diff.

## Критерии приёмки

- Один экземпляр планировщика запускает PHP как пользователь `app` в 03:00 `Europe/Moscow`. Ручной запуск через Makefile и cron используют одну блокировку.
- Деплой использует CLI-образ того же SHA, что и FPM. Планировщик проверяет SHA-тег, работает без bind mount исходников и опубликованных портов и использует существующее окружение CLI.
- Вывод Symfony и код завершения видны в journald. После штатного деплоя Docker возобновляет расписание при перезагрузке хоста.
- Изменения ограничены Compose, workflow сайта, Makefile и документацией. Настройка на production происходит при согласованном деплое.

## Шаги

1. Добавить `site-scheduler`, расписание и общий скрипт запуска в `docker-compose.prod.yml`. Использовать окружение CLI и файлы конфигурации Compose. Логировать запуск и завершение.
2. В `deploy-vashfindir.yml` активировать профиль `scheduler`. Перед миграциями дождаться текущей очистки и остановить планировщик. Запускать контейнер нового релиза после существующих проверок выкладки и сверки тега с FPM.
3. Добавить ручную команду Makefile и остановку сценария отката при работающем планировщике. В README описать расписание, проверку логов, обработку ошибок и номеров Битрикс24, ручной запуск и аварийный откат.
4. Проверить изменения локально, провести независимое ревью только на чтение и открыть отдельный PR.

## Риски и проверки

- **Гонка с ручным запуском или деплоем.** Проверить общий `flock`, отказ параллельного запуска и ожидание активной команды перед остановкой.
- **Чужой или отсутствующий релиз.** Проверить Compose с тестовым SHA, одинаковый CLI-образ и отказ при пустом или изменяемом теге. При неудачной выкладке после остановки планировщика вернуть его только после проверки совместимой пары FPM/CLI и схемы БД.
- **Тихий сбой.** На локальном контейнере с заглушкой PHP проверить cron, передачу stdout/stderr, ненулевой код и доступность журнала после пересоздания контейнера.
- **Простой в 03:00.** BusyBox cron возобновляет расписание со следующего окна. Если окно пропущено, оператор может выполнить один ручной запуск через Makefile.
- **Ошибка конфигурации.** Запустить `docker compose -f docker-compose.prod.yml config` с тестовыми значениями, проверить изменённый workflow через `actionlint` и выполнить `git diff --check`. Для проверок использовать локальные данные и заглушки.

## Результаты проверки

- Compose проверен с тестовым окружением, включая профили `cli` и `scheduler`. Команды Makefile проверены через dry-run. `actionlint` и `bash -n` проверили workflow. Предупреждение SC2016 о существующей отложенной подстановке `PHP_CHECK_COMPOSE` воспроизведено в базовой ветке и исключено из проверки.
- Изолированный Alpine-контейнер с заглушкой PHP подтвердил запуск cron как `app` с окружением CLI, запись stdout/stderr и кода 42 в журнал, отказ параллельного запуска, ожидание при паузе и возобновление после остановки и пересоздания. Вывод проверен через `docker logs`. Доступ к истории системного журнала между контейнерами ограничен правами локальной среды.
- Проверки SSH-сценария с заглушками подтвердили обработку перезапускающегося планировщика и отказ при неполном составе или несовпадении SHA FPM. Проверка Makefile подтвердила остановку отката до любых изменений при работающем планировщике.
- Независимое ревью проведено только на чтение. После правок проверены оба замечания об откате и восстановлении после циклического перезапуска. Новых замечаний среднего уровня и выше нет.
