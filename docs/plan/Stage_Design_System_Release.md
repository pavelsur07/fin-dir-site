# Релиз дизайн-системы v2.2

## Цель и границы

Влить проверенную ветку `design-system` в `master` и развернуть публичный сайт через существующий `deploy-vashfindir.yml`. Меняются Twig-шаблоны, Markdown-оформление, тема Tailwind и собранные assets; бизнес-логика, схема БД, production-конфигурация и соседние сайты не меняются.

## Риск и критерии приёмки

Риск высокий: визуальные изменения охватывают весь публичный сайт и временный Twig Admin. Приёмка: `make ds-check` — 0 нарушений, совпадение `make asset-version` в обоих layout, `make assets-check` и `make ci` проходят, основные страницы и состояния проверены в браузере на 320–1440 px, независимое ревью не содержит незакрытых существенных замечаний. Чужие staged-удаления в рабочем `master` не включать в релиз.

## Порядок

1. Проверить актуальность веток и полный diff; получить независимое read-only ревью.
2. Отправить `design-system`, создать PR в `master` и дождаться обязательного CI `checks`.
3. Влить PR без посторонних файлов. Push в `master` запускает существующий production workflow.
4. Дождаться успешного deploy job и проверить публичный HTTP/health. При сбое остановить дальнейшие действия и разбирать причину по логу workflow.

Откат при подтверждённом дефекте — отдельный revert релизных коммитов в `master` с повторным прохождением CI и деплоя; исходная точка до релиза — `73b6d51`. Миграций БД в ветке нет.
