# Stage 7 — Мини-CRM «Обращения»: отчёт

## Что реализовано

- **Модуль `Lead`:** каждая заявка с формы сайта сохраняется в `lead_lead`, заметки менеджера — в `lead_note`.
- **Каталог форм в коде** (`LeadFormCatalog`):
  - простая `consultation` — имя, контакт, задача, согласие;
  - квалификационная `diagnostics` — плюс три вопроса: «Где продаёте?», «Оборот в месяц», «Что нужно?».

  Одно определение используется и для разметки виджета, и для серверной проверки. Ответы сохраняются снимком с подписями.
- **Виджет `sections/_lead_form.html.twig`** — одна строка include на любой странице. На главной форма теперь боевая, пометка «демо-режим» убрана. На `/ui-kit/sections` показаны оба вида формы (`demo: true`, без отправки).
- **`POST /lead`:**
  - ответы: 201, 422 с ошибками по полям, 403 при чужом Origin, 429 при превышении лимита;
  - без JS — страница результата с `noindex`.
- **Защита:**
  - stateless CSRF по Origin/Referer, без сессии — публичные страницы остаются кешируемыми и без cookie;
  - honeypot;
  - время заполнения меньше 3 секунд → SPAM (ответ как у успеха);
  - лимит 5 валидных заявок за 10 минут с одного IP.
- **Идемпотентность:** `submission_id` (UUID из JS) с уникальным индексом, повтор не создаёт дубль. Без JS id выдаёт сервер: класть его в кешируемую страницу нельзя.
- **Уведомление в Telegram — синхронно и без персональных данных:**
  - в сообщении: номер, форма, страница, ответы, UTM, ссылка на карточку;
  - заявка сохраняется до отправки, сбой Telegram записывается в карточку;
  - повтор: команда `app:lead:notify-pending` или кнопка в карточке.
- **Админка `/admin/leads`:**
  - список с фильтром по статусу и форме и поиском по имени, контакту или части номера;
  - карточка: ответы, источник, UTM, согласие, заметки, другие обращения с тем же контактом, статус и дата следующего контакта (с optimistic lock), повтор уведомления, удаление по запросу субъекта ПД.
- **Хранение данных:** IP и User-Agent не хранятся. От referrer остаётся только origin. Согласие записывается со временем и версией (`LeadConsent::VERSION`).
- **Хранилище лимитов перенесено в Postgres** (`cache.rate_limiter` → `doctrine_dbal`, таблица `cache_items`): счётчики общие для двух реплик и не сбрасываются при деплое. Заодно это исправляет лимит попыток входа в админку из Stage 4.

## Решения и отступления

- **Второй `flush()` в `LeadNotificationSender`:** уведомление — побочный эффект после коммита, отдельно сохраняется только его результат (PATTERNS §5.2).
- **`LeadActionController` ловит `LeadWasModified`** и показывает понятное сообщение вместо страницы 409, как формы Stage 5.
- **JS не добавляет классы** — этого требует `WebsiteFoundationTest`, защита от JS-блокировки прокрутки. Сообщения показываются через атрибут `hidden`, ошибка поля — через `aria-invalid` и вариант `aria-invalid:border-danger` в компонентах полей. Ошибку показывает общий компонент поля.
- **Время заполнения** считается в браузере (`performance.now()`) и приходит как `fill_ms`, поэтому расхождение часов клиента и сервера не даёт ложного SPAM.
- **Лимит тратят только валидные заявки:** человек, исправляющий ошибки в форме, его не исчерпает.
- **Для `navigation.js` отдельный файл не заводился,** Makefile и asset pipeline не менялись.
- **Попутные мелочи:** у `_form_input` появился необязательный параметр `autocomplete`, в `deptrac` добавлены слои `Command`, `Twig`, `TwigVendor`, Adapter видит Symfony, Service видит Adapter.

## Ревью

- **Self-review:**
  - восстановлены CRLF в `home.html.twig`;
  - удалена дублирующая миграция, которую сгенерировал зависший интерактивный `migrations:diff` (теперь запуск только с `--no-interaction`);
  - исправлено отображение ошибки чекбокса.
- **Claude Code review:** blocker и high нет, 6 medium, все исправлены:
  1. апостроф в UTM ломал HTML для Telegram → `ENT_HTML401`;
  2. числовой ключ в POST давал 500 → проверка `is_string`;
  3. лимит тратили ошибочные попытки → расход только после валидации;
  4. лимит считался на каждой реплике отдельно и сбрасывался при деплое → Postgres;
  5. расхождение часов клиента давало ложный SPAM → `fill_ms` по часам браузера;
  6. недостающие тесты — добавлены.

  Также исправлены low: back-link и `page_url` по одной строгой регулярке, referrer только origin, `+` с 10 цифрами, поиск по части номера и через «8», экранирование LIKE, `autocomplete`, русские сообщения.
- **Повторное ревью:** blocker, high и medium нет. Low про переводы строк в уведомлении, строгий `page_url`, порядок атрибутов в JS и поиск через «8» исправлены.
- **Известные ограничения, принято осознанно:**
  - после отправки уведомления растёт `version` — возможен редкий ложный «изменили в другом окне» в открытой карточке;
  - гонка через уникальный индекс `submission_id` обработана, но не покрыта тестом: без подмены репозитория её не воспроизвести;
  - синхронная отправка: при сбое Telegram ответ формы задерживается до 3 секунд;
  - без JS обновление страницы результата может создать дубль;
  - проверка времени заполнения — фильтр, а не защита: бот может не прислать `fill_ms`. От ботов защищают honeypot и лимит;
  - лимит без `symfony/lock`: параллельные запросы с двух реплик могут немного его превысить;
  - просроченные строки `cache_items` удаляются только через `cache:pool:prune`, нужен cron вместе с `notify-pending`;
  - регионы `role="status"`/`role="alert"` показываются снятием `hidden`, не все экранные дикторы их объявляют. Ссылки на согласие не связаны с чекбоксом через `aria-describedby`, компонент этого не поддерживает.

## Перед релизом (действия пользователя)

1. Создать бота у @BotFather, добавить его в чат для заявок и узнать `chat_id`.
2. Завести GitHub secrets `VF_TELEGRAM_BOT_TOKEN` и `VF_TELEGRAM_LEAD_CHAT_ID`. Без них заявки сохраняются, но уведомлений не будет.
3. После деплоя отправить тестовую заявку с главной и убедиться, что сообщение пришло. Лучше с UTM, содержащим апостроф: `?utm_campaign=o'test`. Затем удалить тестовую заявку в админке.
4. Позже, отдельной задачей:
   - cron для `app:lead:notify-pending` и `cache:pool:prune cache.rate_limiter`;
   - срок хранения обращений (152-ФЗ);
   - размещение формы «Диагностика» (вопросы можно поправить в `LeadFormCatalog`).
