# Traefik — reverse-proxy хоста

Общий на весь сервер: терминирует TLS, выпускает сертификаты Let's Encrypt и
раздаёт трафик по контейнерам. Раньше жил только в `/opt/traefik` на сервере,
вне git — без истории, без ревью и без возможности развернуть заново.

## Разделение ответственности

| | Где описано |
|---|---|
| Entrypoints, ACME, провайдер | здесь, `docker-compose.yml` |
| Маршруты, домены, редиректы | в метках приложения, `docker-compose.prod.yml` |

Смешивать не нужно: Traefik читает метки через docker-провайдер, поэтому новый
сайт добавляется правкой только своего compose-файла, без касания этого.

## Ограничение по версии

**Не ниже `v3.6.1`.** До этой версии Traefik жёстко использует Docker API 1.24,
а Docker Engine 29 требует минимум 1.44. Провайдер отваливается молча: роутов не
остаётся, хост отвечает `404 page not found` на все домены и при этом продолжает
отдавать валидный TLS из сохранённого `acme.json`. Симптом читается как поломка
приложения, хотя приложение исправно.

Диагностика:

```bash
docker logs --tail=100 traefik 2>&1 | grep "is too old"   # ожидаем 0 строк
```

Признак этой аварии снаружи — `404` с `content-type: text/plain` и
`content-length: 19` на **любом** домене хоста.

## Что секретно

| В git | Только на сервере |
|---|---|
| `docker-compose.yml`, `.env.example`, этот файл | `.env` с `ACME_EMAIL` |
| | том `traefik_letsencrypt` — приватные ключи сертификатов |

Том бэкапить не нужно: Let's Encrypt перевыпустит сертификаты автоматически.
Единственная плата за потерю тома — упереться в rate limit при частых
пересозданиях, поэтому просто не удаляйте его без причины.

## Развернуть на чистом хосте

Предварительно: A-записи доменов указывают на этот сервер, порты 80 и 443
открыты снаружи (без 80 не пройдёт TLS-ALPN проверка Let's Encrypt),
установлены Docker и Compose v2.

```bash
git clone https://github.com/pavelsur07/fin-dir-site.git
cd fin-dir-site/infra/traefik
cp .env.example .env && ${EDITOR:-nano} .env    # вписать реальный ACME_EMAIL
make -C ../.. traefik-up
```

`traefik-up` сам создаст сеть `traefik_web`, если её нет, и поднимет стек.

Имена сети и тома заданы явно через `name:`, поэтому не зависят от имени
каталога, из которого запущен compose. Без этого имя склеивалось бы из имени
каталога — и разворачивание из каталога с другим именем дало бы пустой том с
перевыпуском сертификатов и сеть, которую приложения не найдут.

Сеть объявлена `external` **с обеих сторон** — и здесь, и в приложении. Она
общая шина хоста: если бы ею владел один стек, его `docker compose down` снёс
бы связность всем остальным. Владельца нет ни у кого, поэтому и создаётся она
отдельным шагом.

## Обслуживание

```bash
make traefik-config    # проверить синтаксис и увидеть, что развернётся
make traefik-up        # применить изменения
make traefik-logs      # логи
```

Прод обновляется автоматически: workflow `deploy-traefik.yml` срабатывает на
изменения в `infra/traefik/**`. Он намеренно отделён от деплоя приложения —
общая инфраструктура не должна меняться при каждом релизе сайта.

## Конвенции

Канон — имена этого хоста. Их используют метки в `docker-compose.prod.yml`:

| | значение |
|---|---|
| сеть | `traefik_web` |
| entrypoints | `web` (:80), `websecure` (:443) |
| certresolver | `le` |

Хост `vf-app` (217.198.13.171, проект `2bstock-app`) исторически использует
другой набор — `traefik-public` / `http` / `https` / `letsEncrypt`. Из-за этого
блоки меток непереносимы между хостами. Приведение `vf-app` к общему набору —
отдельная задача в его репозитории, отсюда он не управляется.

## Известные ограничения

Traefik получает сокет Docker (пусть и `:ro`) — это фактически root-доступ к
хосту для этого контейнера. Стандартная для Traefik схема, но при ужесточении
требований ставится docker-socket-proxy, отдающий только нужные read-эндпоинты.
Сейчас не сделано осознанно: лишний сервис ради угрозы, которая на однопроектном
хосте не реализуется.
